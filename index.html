처음에는 HTML, CSS, JavaScript를 몰라도 파일 딱 하나(index.html)만 있으면 웹사이트가 뚝딱 만들어집니다. 먼저 성공 경험을 맛본 뒤, 기능을 추가할 때 왜 단일 파일 방식이 무너지는지 직접 확인해 봅니다.

프롬프트 1-1 단일 파일(index.html)로 1인 1역할 배정 앱 최초 생성
교실에서 사용할 '학급 1인 1역할 배정 웹 애플리케이션'을 만들고 싶어. 초보자도 바로 깃허브에 올릴 수 있도록 HTML, CSS, JavaScript를 분리하지 말고 반드시 `index.html` 파일 딱 하나에 모든 코드를 통합해서 작성해 줘. [필수 기능] 1. 왼쪽 영역: 학생 이름 목록을 줄바꿈(엔터)으로 여러 명 입력할 수 있는 입력창 (기본 예시로 학생 10명 이름을 미리 넣어줘) 2. 오른쪽 영역: 학급 1인 1역할 목록을 줄바꿈으로 입력할 수 있는 입력창 (예: 칠판 지우기, 우유 당번, 분리수거, 창문 환기 등 10개 기본 입력) 3. 중앙의 [🎲 역할 랜덤 배정하기] 버튼을 누르면 학생과 역할을 무작위로 1:1 매칭해서 아래쪽에 보기 좋은 카드 형태로 출력해 줘. 4. 교실 TV 화면에 띄워놓고 볼 수 있도록 글씨를 큼직하게 하고 밝고 따뜻한 학급 게시판 디자인으로 꾸며줘.
프롬프트 1-2 (한계 체험용) 단일 파일 상태에서 복잡한 기능 추가 & 디자인 변경 요청하기
방금 만든 `index.html` 파일에 다음 4가지 기능을 한꺼번에 추가해서 수정해 줘. 내가 통째로 복사해서 다시 덮어쓸 수 있도록 생략 없이 전체 코드를 다 출력해 줘. 1. 역할 배정 버튼을 눌렀을 때 2초 동안 두구두구 섞이는 듯한 슬롯머신 애니메이션 효과 추가 2. 특정 학생에게 역할을 먼저 고정(지정)해 두고 나머지 학생만 랜덤으로 돌리는 '사전 고정 핀' 기능 추가 3. 전체 화면 테마를 파스텔 민트 & 코랄 톤으로 전면 교체하고, 교실 인쇄용 [🖨️ A4 출력하기] 버튼 스타일 추가 4. 배정 완료 시 화면에 꽃가루(Confetti)가 흩날리는 시각 효과 추가

💡선생님들과 함께 이야기 나눌 포인트 (왜 `index.html` 하나만 쓰면 힘들까요?)

  • 전체 재출력 대기와 코드 생략(`// ... 기존 코드 ...`) 참사: 버튼 색깔 하나만 바꾸고 싶어도 AI가 500줄짜리 전체 코드를 처음부터 끝까지 다시 다 쓸 때까지 기다려야 합니다. 코드가 길어지면 AI가 중간 코드를 멋대로 생략해 버려 붙여넣는 순간 앱이 먹통이 됩니다.
  • 연쇄 고장 (Side Effect): 디자인(CSS)만 고쳐달라고 했는데 AI가 전체 코드를 다시 출력하면서 멀쩡히 잘 작동하던 뽑기 로직(JS)을 슬쩍 바꿔버려 기능이 고장 납니다.
  • GitHub 수동 업로드의 피로감: 오타 하나를 고쳐도 GitHub 웹페이지에서 기존 파일을 삭제하거나 열고, 전체 코드를 붙여넣고 커밋하는 과정을 매번 반복해야 합니다.

검증된 표준 코드 Apps Script (code.gs) 붙여넣기용 완성 코드 (시트 자동초기화 + CORS 완벽 대응) 
// [학급 1인 1역할 배정 앱] Google Apps Script (code.gs)
// 1. 시트 탭이 없으면 자동으로 생성하고 기본 예시 데이터를 채워줍니다.
// 2. GitHub Pages 외부 접속 시 CORS 에러가 나지 않도록 JSON 텍스트 응답을 반환합니다.

function doGet(e) {
  initSheetsIfNeeded();
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  
  const studentRows = ss.getSheetByName('학생명단').getDataRange().getValues();
  const roleRows = ss.getSheetByName('역할목록').getDataRange().getValues();
  const resultRows = ss.getSheetByName('배정결과').getDataRange().getValues();

  const students = studentRows.slice(1).filter(r => r[1]).map(r => ({ num: r[0], name: String(r[1]).trim() }));
  const roles = roleRows.slice(1).filter(r => r[0]).map(r => ({ role: String(r[0]).trim(), desc: String(r[1] || '').trim() }));
  const results = resultRows.slice(1).filter(r => r[2]).map(r => ({
    date: r[0], num: r[1], name: r[2], role: r[3], desc: r[4] || ''
  }));

  const payload = { status: 'success', students, roles, results };
  return ContentService.createTextOutput(JSON.stringify(payload))
    .setMimeType(ContentService.MimeType.JSON);
}

function doPost(e) {
  try {
    initSheetsIfNeeded();
    const body = JSON.parse(e.postData.contents);
    const ss = SpreadsheetApp.getActiveSpreadsheet();

    // 배정 결과 저장 요청 처리
    if (body.action === 'saveResults' && Array.isArray(body.assignments)) {
      const sheet = ss.getSheetByName('배정결과');
      sheet.clearContents();
      sheet.appendRow(['배정일시', '번호', '이름', '담당역할', '역할설명']);
      const now = Utilities.formatDate(new Date(), 'Asia/Seoul', 'yyyy-MM-dd HH:mm');
      body.assignments.forEach(item => {
        sheet.appendRow([now, item.num || '', item.name, item.role, item.desc || '']);
      });
      return ContentService.createTextOutput(JSON.stringify({ status: 'success', message: '배정 결과가 구글 시트에 저장되었습니다.' }))
        .setMimeType(ContentService.MimeType.JSON);
    }

    // 명단 및 역할 목록 업데이트 요청 처리
    if (body.action === 'updateLists') {
      if (Array.isArray(body.students)) {
        const sSheet = ss.getSheetByName('학생명단');
        sSheet.clearContents();
        sSheet.appendRow(['번호', '이름']);
        body.students.forEach((s, idx) => sSheet.appendRow([s.num || idx + 1, s.name]));
      }
      if (Array.isArray(body.roles)) {
        const rSheet = ss.getSheetByName('역할목록');
        rSheet.clearContents();
        rSheet.appendRow(['역할명', '역할설명']);
        body.roles.forEach(r => rSheet.appendRow([r.role, r.desc || '']));
      }
      return ContentService.createTextOutput(JSON.stringify({ status: 'success', message: '명단과 역할이 업데이트되었습니다.' }))
        .setMimeType(ContentService.MimeType.JSON);
    }

    return ContentService.createTextOutput(JSON.stringify({ status: 'error', message: '알 수 없는 요청입니다.' }))
      .setMimeType(ContentService.MimeType.JSON);
  } catch (err) {
    return ContentService.createTextOutput(JSON.stringify({ status: 'error', message: err.toString() }))
      .setMimeType(ContentService.MimeType.JSON);
  }
}

function initSheetsIfNeeded() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  if (!ss.getSheetByName('학생명단')) {
    const s = ss.insertSheet('학생명단');
    s.appendRow(['번호', '이름']);
    [['1', '김민준'], ['2', '이서연'], ['3', '박도윤'], ['4', '최지우'], ['5', '정하은'], ['6', '강시우']].forEach(r => s.appendRow(r));
  }
  if (!ss.getSheetByName('역할목록')) {
    const r = ss.insertSheet('역할목록');
    r.appendRow(['역할명', '역할설명']);
    [['칠판당번', '수업 후 칠판 깨끗이 지우기'], ['환기당번', '쉬는 시간마다 창문 열기'], ['우유당번', '급식실 우유 바구니 운반'], ['분리수거', '재활용 쓰레기통 정리'], ['불끄기당번', '이동수업 시 교실 소등'], ['바닥쓸기', '교실 뒷자리 바닥 정돈']].forEach(row => r.appendRow(row));
  }
  if (!ss.getSheetByName('배정결과')) {
    const res = ss.insertSheet('배정결과');
    res.appendRow(['배정일시', '번호', '이름', '담당역할', '역할설명']);
  }
}
프롬프트 4-1 (AI Studio Build 입력용) 내 웹앱(script.js / index.html)에 구글 Apps Script 웹앱 URL 연결하기
현재 만든 1인 1역할 배정 앱을 구글 스프레드시트(Apps Script 웹앱)와 연결해서 데이터를 저장하고 불러오고 싶어. 내가 배포한 Apps Script 웹앱 주소(URL)는 다음과 같아: [여기에_복사한_웹앱_URL_붙여넣기] (또는 화면 상단에 [⚙️ 시트 URL 설정] 입력창을 만들어서 웹 화면에서 주소를 붙여넣고 localStorage에 저장할 수 있게 해줘.) [연동 필수 조건 - 매우 중요!] 1. 구글 시트에서 데이터 불러오기 (GET 요청): - 페이지가 열릴 때 및 [🔄 시트에서 명단/결과 불러오기] 버튼을 누르면 웹앱 URL로 GET 요청을 보내서 `students`, `roles`, `results` 데이터를 가져와 화면에 표시해 줘. - 위 code.gs의 실제 응답 형식을 반드시 따라줘: { status: "success", students: [{ num: 1, name: "김민준" }], roles: [{ role: "칠판당번", desc: "칠판 닦기" }], results: [{ date: "2026-10-17 09:00", num: 1, name: "김민준", role: "칠판당번", desc: "칠판 닦기" }] }. - students와 roles는 문자열 배열이 아니라 객체 배열이야. 학생 이름은 student.name, 번호는 student.num, 역할명은 role.role, 설명은 role.desc를 사용해 줘. 객체 자체를 문자열로 바꾸거나 배열에 바로 join을 적용하면 [object Object]가 표시되므로 금지해 줘. - 기존 직접 입력 방식의 문자열 배열은 입력 경계에서 객체 배열로 변환하고, 이후 불러오기·랜덤 배정·카드 표시·저장에서는 같은 객체 구조를 유지해 줘. 시트의 번호는 유지하고, 학생 이름이나 번호를 다시 추측해서 만들지 마. - 텍스트 영역에는 students.map(s => s.name).join('\n'), 역할 입력에는 roles.map(r => r.role).join('\n')처럼 문자열 필드만 표시해 줘. 입력을 수정하지 않은 경우 원래 번호와 역할 설명을 그대로 보존해 줘. - 카드의 이름과 역할, 선택 상자의 표시 문구에는 textContent를 사용해 줘. 저장된 results도 result.name과 result.role로 표시해 줘. - HTTP 오류, status가 success가 아닌 응답, 배열이 아닌 students/roles/results는 오류로 안내하고 기존 화면 데이터를 유지해 줘. 이름이 비어 있는 행은 제외하고 이름이 객체인 잘못된 응답은 표시하지 마. 2. 배정 결과 저장하기 (POST 요청 - CORS 에러 방지 필수): - [💾 배정 결과 구글 시트에 저장] 버튼을 누르면 웹앱 URL로 `fetch` POST 요청을 보내줘. - 주의: GitHub Pages에서 구글 Apps Script로 POST 요청을 보낼 때 CORS 에러(Preflight 차단)가 발생하지 않도록, 반드시 `headers: { "Content-Type": "text/plain;charset=utf-8" }`로 설정하고 `body: JSON.stringify({ action: "saveResults", assignments: [...] })` 형태로 전송해 줘. - assignments의 각 항목은 { num: student.num, name: student.name, role: selectedRole.role, desc: selectedRole.desc }로 구성해 줘. name이나 role에 객체 전체를 넣지 마. 3. 통신 중에는 버튼에 '불러오는 중...', '저장 중...' 로딩 상태를 표시해서 교사가 진행 상황을 알 수 있게 해줘.

학생 이름이 [object Object]로 보일 때: 기존 앱 수정 요청

시트에서 불러온 학생 이름이 [object Object]로 표시되는 오류를 수정해 줘. Apps Script GET 응답은 students: [{ num: 1, name: "김민준" }], roles: [{ role: "칠판당번", desc: "칠판 닦기" }], results: [{ date: "2026-10-17 09:00", num: 1, name: "김민준", role: "칠판당번", desc: "칠판 닦기" }] 형식이야. 현재 불러오기 함수부터 입력창, 학생 선택, 랜덤 배정, 결과 카드, 저장 함수까지 확인해 줘. 객체를 그대로 출력하거나 String(student), students.join('\n')을 사용하지 말고 student.name을 표시해 줘. 역할은 role.role을 표시해 줘. 학생·역할 상태는 객체 배열로 유지하고 입력창에만 students.map(s => s.name).join('\n')과 roles.map(r => r.role).join('\n')을 사용해 줘. 이름·역할명은 textContent로 표시하고 원래 학생 번호와 역할 설명은 보존해 줘. 저장할 assignments는 { num, name, role, desc } 구조이며 name과 role은 문자열이어야 해. 잘못된 응답은 오류를 안내하고 기존 데이터를 유지해 줘. 시트의 이름 표시 → 역할 배정 → 저장 → 다시 불러오기까지 검증해 줘. 기존 URL 설정과 다른 기능은 유지해 줘.

이 페이지는 연수 안내서입니다. 위 수정 요청을 실제로 만든 학급 앱의 코드와 함께 AI Studio 등에 전달한 뒤, 수정된 앱을 GitHub에 반영하세요. 안내 페이지 업데이트만으로 별도 앱의 코드는 변경되지 않습니다.

🚨 Apps Script 배포 시 선생님들이 가장 많이 막히는 3가지 체크포인트

  1. 액세스 권한 설정: [배포] → [새 배포] → 유형: 웹 앱 선택 후, 액세스 권한이 있는 사용자를 반드시 ‘모든 사용자(Anyone)’로 변경해야 외부 GitHub Pages에서 접속됩니다.
  2. 안전하지 않은 앱 경고창 통과: 최초 배포 시 권한 승인 창에서 [고급] 글씨를 누르고 하단의 [프로젝트명(안전하지 않음)으로 이동] → [허용]을 눌러야 배포가 완료됩니다.
  3. URL 끝자리 확인: 복사한 웹 앱 URL이 반드시 .../exec로 끝나는지 확인하세요. (테스트용 .../dev 주소는 본인 외에 작동하지 않습니다.)

프롬프트 5-1: 이전 역할 중복 방지 기능 추가
기존 구글 시트 연동 코드는 절대 건드리지 말고, `script.js`의 랜덤 배정 알고리즘만 업그레이드해 줘. 시트에서 불러온 직전 `results`(이전 배정 결과)를 참고해서, 각 학생이 지난번에 맡았던 역할과 동일한 역할에는 배정되지 않도록 제외하고 섞어주는 '이전 역할 중복 방지' 체크박스 옵션을 추가해 줘.
프롬프트 5-2: 학급 게시판용 A4 인쇄 모드
`script.js`의 기능은 그대로 유지하고 `style.css`와 `index.html`만 수정해 줘. 화면 상단에 [🖨️ 학급 게시판용 인쇄] 버튼을 만들고, 인쇄할 때는(`@media print`) 입력창과 설정 버튼들을 모두 숨기고 '이달의 1인 1역할 배정표' 제목과 배정 결과 카드만 A4 한 장에 딱 맞게 깔끔한 표 형태로 출력되도록 스타일을 추가해 줘.

📌 핵심 주의사항: code.gs를 수정했을 때는 어떻게 하나요?

HTML, CSS, JS는 GitHub에 커밋하면 1~2분 뒤 웹사이트에 자동 반영되지만, Apps Script(code.gs)는 저장(Ctrl+S)만 해서는 반영되지 않습니다!
반드시 Apps Script 우측 상단 [배포] → [배포 관리] → 상단 연필 아이콘(수정) → 버전: [새 버전] 선택 → [배포]를 눌러야 기존 웹앱 URL이 바뀌지 않으면서 새 코드가 적용됩니다.

연수 현장에서 선생님들이 손을 들었을 때 10초 안에 해결해 줄 수 있는 체크리스트입니다.

Q1. "저장 버튼을 눌렀는데 구글 시트에 아무것도 안 적히고 콘솔에 CORS 에러가 떠요!"

원인 및 해결:① Apps Script 배포 시 '액세스 권한이 있는 사용자'가 '모든 사용자'로 되어 있는지 확인하세요. ② `script.js`에서 `fetch` POST 요청 시 헤더가 `application/json`으로 되어 있으면 구글이 차단합니다. AI에게 headers: { "Content-Type": "text/plain;charset=utf-8" }로 바꿔달라고 지시하세요.

Q2. "GitHub에 커밋했는데 내 사이트 주소로 들어가도 옛날 화면 그대로예요!"

원인 및 해결: GitHub Pages 서버가 새 파일을 반영하는 데 약 1분 정도 걸리며, 브라우저가 이전 화면(캐시)을 기억하고 있어서 그렇습니다. 키보드에서 Ctrl + Shift + R (강력 새로고침)을 눌러보세요.

Q3. "code.gs 코드를 고치고 저장(Ctrl+S)했는데 웹앱 동작이 안 바뀌어요!"

원인 및 해결: Apps Script는 저장만 하면 기존 배포본에 반영되지 않습니다. 우측 상단 [배포] → [배포 관리] → 연필 아이콘 클릭 → 버전을 [새 버전]으로 선택 후 [배포]를 눌러야 반영됩니다.

Q4. "AI가 코드를 고쳐주다가 기존에 잘 되던 버튼을 지워버렸어요!"

원인 및 해결: 프롬프트 끝에 "기존에 구현된 모든 버튼과 구글 시트 연동 함수는 절대 삭제하거나 생략하지 말고 유지한 상태에서 OO 기능만 추가해 줘"라는 방어 문구를 꼭 붙여주세요.
